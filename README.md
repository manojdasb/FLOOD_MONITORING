# India Flood Monitor

A lightweight, open-source flood early-warning dashboard for two flood-prone Indian river zones, built with Python and Streamlit. It combines modelled river discharge, rainfall, flood return-period thresholds and (optionally) Sentinel-1 satellite water mapping, and is explicit about how old each piece of data is.

**Repository:** <https://github.com/manojdasb/FLOOD_MONITORING>

<!-- Live demo: add your Streamlit Community Cloud URL here after deploying -->

> **Status: prototype.** This tool is for learning, research and demonstration. It uses *modelled* discharge, not official gauge readings, and has not yet been validated against CWC data. **Do not use it for emergency decisions.** For official flood information, use the [CWC Flood Forecasting portal](https://ffs.india-water.gov.in) and your state disaster management authority.

## Features

- **River discharge and 7-day forecast** from Copernicus GloFAS (via Open-Meteo), shown with the last 30 days.
- **Flood thresholds** (2-, 5- and 20-year return periods) computed from the 1984-2022 GloFAS history using a Gumbel fit.
- **Rainfall** for the past 24 h and next 24 h, plus the current rate, from 15-minute weather data.
- **Status levels:** `NOMINAL`, `WARNING` (above the 2-year flood) and `CRITICAL` (above the 5-year flood), with a 7-day outlook based on the forecast peak.
- **Live clock** (IST and UTC) that ticks every second.
- **Data freshness table:** every source shows its data timestamp, when it was fetched and how old it is.
- **Optional Sentinel-1 water extent** from the latest satellite scene (Microsoft Planetary Computer).
- **Resilient:** if a source fails, a banner appears, the app keeps running and retries automatically.
- **No API keys or secrets needed.**

## How "real-time" is it?

Honest answer: it depends on the layer.

| Layer | Source | Underlying cadence | App re-pulls |
|---|---|---|---|
| Clock | Server time | Every second | Every second |
| Rainfall | Open-Meteo Forecast API | 15-minute model data | Every 5 min |
| River discharge | Open-Meteo Flood API (GloFAS) | **Daily model** | Every 30 min |
| Flood thresholds | GloFAS 1984-2022 reanalysis | Static history | Every 24 h |
| Water extent (optional) | Sentinel-1 SAR | New scene every ~6-12 days | Every 6 h |

River discharge comes from a daily hydrological model, so its value changes about once a day, even though the app checks more often. It is **not** a live gauge reading.

## Quick start

Requires Python 3.9+.

```bash
git clone https://github.com/manojdasb/FLOOD_MONITORING.git
cd FLOOD_MONITORING

python -m venv .venv
# Windows:  .venv\Scripts\activate
# macOS/Linux:  source .venv/bin/activate

pip install -r requirements.txt
streamlit run app.py
```

Then open <http://127.0.0.1:8501>.

### Enable the Sentinel-1 panel (optional)

Uncomment the satellite lines in `requirements.txt` (`rasterio`, `pystac-client`, `planetary-computer`), run `pip install -r requirements.txt` again, and tick **Sentinel-1 satellite water extent** in the sidebar. The first load is slow because it reads a satellite window over the network.

## How it works

```
Open-Meteo Flood API  --> discharge (30 days + 7-day forecast) --+
Open-Meteo Flood API  --> 1984-2022 history --> Gumbel fit ------+--> status + charts
Open-Meteo Forecast   --> rainfall (past/next 24 h) -------------+
Sentinel-1 (optional) --> water extent ---------------------------+
                                                                   v
                                                         Streamlit dashboard
                                                  (1 s clock, 30 s refresh check)
```

**Status logic**

- `CRITICAL`: discharge is at or above the 5-year flood.
- `WARNING`: discharge is at or above the 2-year flood.
- `NOMINAL`: otherwise.
- The 7-day outlook applies the same rules to the forecast peak.

**Return-period thresholds.** Annual maximum discharge is extracted from the 1984-2022 series and fitted with a Gumbel distribution. The discharge for return period *T* is `loc - beta * ln(-ln(1 - 1/T))`.

**Choosing the river cell.** GloFAS is a 5 km grid, so the exact station coordinates can fall on a tributary or a dry cell. The app checks the surrounding 3x3 grid (0.05 degree steps) and uses the cell with the largest discharge.

## Adding a zone

Add an entry to `ZONES` in `data_sources.py`:

```python
"zone3": Zone("zone3", "Zone 3 - Godavari (Rajahmundry)", "Godavari",
              "Rajahmundry", 17.00, 81.78, (81.60, 16.90, 81.95, 17.10)),
```

To use the satellite panel for the new zone, also add its bounding box to `AOIS` in `spatial_processor.py`.

## Limitations

- **Modelled, not measured.** Discharge is GloFAS model output at roughly 5 km resolution. It can differ from what a river gauge records, especially on large braided rivers such as the Brahmaputra.
- **No gauge water level.** CWC danger and warning marks are gauge heights (metres) and cannot be compared with discharge (m3/s). The CWC does not publish a documented public API for live gauge readings.
- **Thresholds are statistical,** derived from model reanalysis, and are not official flood stages.
- **Sentinel-1 water area** counts permanent water (the river itself) as well as floodwater, and depends on satellite pass times.
- **Not validated** against observed floods or CWC records yet.
